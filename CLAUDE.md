# fib-bot — контекст проекта для Claude Code

Этот файл читается автоматически при каждом запуске `claude` в этой папке.
Он написан потому, что Claude Code на сервере НЕ видит ни проект claude.ai
"Междусабойчик" (где лежат регламент, бриф, архитектура, список инструментов),
ни память предыдущих сессий. Всё, что здесь написано — это перенесённый контекст,
а не догадки.

---

## Что это за система

Телеграм-бот, который скринит активы на сетапы по Фибоначчи и присылает алерт,
когда цена уходит в глубокую коррекцию (0.618 и глубже).

**Это боевая система, а не песочница.** Сигналы получают три реальных человека
(Леонид, Сергей, Pavel), которые по ним принимают торговые решения. Всё, что
ломает бота, ломает его для них.

Работает автономно с 24 августа 2026 двумя ветками через cron root-пользователя:

| Что | Как часто | Файл запуска |
|---|---|---|
| Точечный watch по IBM | каждые 15 минут (`*/15 * * * *`) | `run_live.sh` → `orchestrator.py` |
| Скринер по 14 инструментам | раз в час (`0 * * * *`) | `run_screener.sh` → `screener.py` |

Обе ветки шлют алерт только при коррекции 0.618/0.786/1.0, с памятью
(не дублируют один и тот же уровень), и при реальном срабатывании отправляют
**два сообщения**: сначала PNG-график (`sendPhoto`), следом полный текст.

## Архитектура: 6 агентов

Поток: `Data → Fibo → Price-Behavior → Verification → (Intraday, Context) → Dispatch`

| Модуль | Роль |
|---|---|
| `agents/data_agent.py` | Котировки FMP: `load_fmp_daily()` (дневные), `load_fmp_intraday()` (1H/4H) |
| `agents/fibo_agent.py` | Точки по теням, сетка уровней. Два независимых метода поиска экстремумов |
| `agents/price_behavior_agent.py` | Тест / пробой / закрепление / ретест / ложный пробой + подтверждение объёмом |
| `agents/verification_agent.py` | Чек-лист + сверка двух методов построения структуры (НЕ блокирует отправку) |
| `agents/intraday_agent.py` | Подтверждение на 1H/4H (раздел 7.3 регламента) |
| `agents/context_agent.py` | Макро-календарь FMP (ФРС, CPI, NFP, ВВП, ОПЕК+) — пометка поверх алерта |
| `agents/chart_agent.py` | PNG-график, тёмная тема, matplotlib |
| `agents/dispatch_agent.py` | Формат сообщения (раздел 24) + отправка в Telegram |

Отдельно: `backtest.py` — walk-forward симуляция, `screener.py` — цикл по 14 инструментам.

## Методология — правила, которые нельзя менять молча

Полный регламент живёт в проекте claude.ai (`claude/fibonacci-reglament.md`) и
пока не перенесён сюда. Ключевое, что закодировано и подтверждено Леонидом:

- **Конвенция точка1/точка2 перевёрнута относительно многих платформ.**
  Точка 1 = 100% = начало движения. Точка 2 = 0% = конец движения.
  Для ВОСХОДЯЩЕГО движения точка 1 = LOW, точка 2 = HIGH.
  Из этого следует: **инвалидация = цена точки 1, цель = цена точки 2.**
  Это подтверждено 31 августа, не пересматривать без прямого указания Леонида.
- **Точки берутся по теням** (не по телам), подтверждение точки — минимум
  5 баров слева.
- **Раздел 7.1:** глобальный экстремум ищется только внутри переданного окна;
  правило — "самый старый непробитый экстремум".
- **Раздел 7.3** (окна для внутридневного подтверждения — рабочий дефолт Claude,
  НЕ число от команды): 1H — потолок 15 торговых дней, 4H — 60 торговых дней.
  Если команда Леонида пришлёт свой список баров по ТФ — он имеет приоритет
  и заменяет эти числа.
- **Порог алерта: 0.618 / 0.786 / 1.0.** Уровни 0.236/0.382 — не повод для алерта.
- **Цвет 0.786 — зелёный, закреплён регламентом** (раздел 16). Остальные цвета
  графика — временная рабочая палитра, не финал.
- **Раздел 2 регламента — главное правило проекта:** не имитировать результат.
  Если данных не хватает — честно сказать, что не хватает, а не подставить
  правдоподобное число. Это относится и к коду (`insufficient_data` вместо
  выдуманного исхода в бэктесте), и к ответам в чате.
- **Раздел 25:** при конфликте методик нельзя молча выбрать вариант — надо
  спросить Леонида.

## Правила работы на этом сервере

**Никогда:**
- Не выводить содержимое `.env` в консоль, в файлы, в git, в чат. Там реальные
  `TELEGRAM_BOT_TOKEN` и `MARKET_DATA_API_KEY`. Секреты читаются только через
  `source .env` внутри shell-обёрток.
- Не запускать ничего, что реально шлёт в Telegram, без явного разрешения в
  этом конкретном разговоре. Скрипты `preview_*.py` рассылают по-настоящему
  всем троим — это не тесты.
- Не трогать `crontab` без явной просьбы. Сейчас там ровно две строки,
  проверяется через `crontab -l`.
- Не удалять и не переписывать `output/alert_state.json` и
  `output/screener_state.json` — это память level-watch между запусками.
  Их порча = поток дублирующих алертов у трёх человек.

**Всегда:**
- Перед любым изменением кода агентов — запустить `python3 tests/test_pipeline.py`
  (ожидается **63/63**) и `python3 tests/test_intraday_agent.py` (**20/20**).
  После изменения — запустить снова. Падение регрессии = откат, а не "поправим потом".
- Продакшен-путь проверять живым прогоном, а не только тестами: раньше каждый
  деплой подтверждался реальным выводом сервера.
- Изменения в код агентов вносить точечно. Файлы на сервере — источник истины;
  GitHub-репозиторий (`github.com/leonid14022003-eng/fib-bot`) отстал с 24 августа
  и НЕ является актуальной копией.

## Как Леонид просит с ним разговаривать

- Без преамбулы и разгона. Сначала самое полезное, неудобную правду — первой,
  а не в конце.
- Без валидационных зачинов ("Отличный вопрос", "Совершенно верно" и подобных).
- Помечать уверенность: **[Точно]** — хорошо подтверждено, **[Вероятно]** —
  обоснованный вывод, **[Предположительно]** — заполнение пробела. Если ответ
  в основном догадки — сказать это прямо.
- При несогласии — причина, конкретная альтернатива, конкретный риск его подхода.
- Держать позицию под давлением, если не появилось новых фактов.
- Язык общения — русский.
