# fib-bot -- черновая реализация мультиагентного пайплайна

Первая рабочая версия логики из `claude/multi-agent-architecture.md` (проект
"Междусабойчик"). Прогнана end-to-end на реальных дневных данных IBM и
покрыта юнит-тестами. Это ядро анализа -- не сам 24/7-бот (постоянный цикл
на VPS сюда ещё не подключён, см. "Чего здесь нет" ниже).

## Как запустить

```
cd fib-bot
pip install -r requirements.txt  # нужно только для load_fmp_daily() -- requests
python3 tests/test_pipeline.py   # юнит-тесты логики (синтетические фикстуры), без внешних зависимостей
python3 orchestrator.py          # прогон на демо-данных IBM (офлайн, из data/ibm_daily_raw.txt)
```

Питон 3.10+. Для реального источника данных (FMP) нужен `requests` (см.
`requirements.txt`) и сетевой доступ -- это единственная внешняя зависимость
во всём проекте, и она нужна только на VPS, не для локальных тестов.

## Структура

```
agents/
  data_agent.py            -- свечи: демо-загрузчик (офлайн) + load_fmp_daily() (продакшен)
  fibo_agent.py             -- поиск HIGH/LOW по теням, построение ФИБО (глобальный + локальный)
  price_behavior_agent.py   -- ближайший уровень, тесты/пробои/ложные пробои
  verification_agent.py     -- чек-лист раздела 23 регламента + сверка нескольких прогонов
  dispatch_agent.py         -- финальное сообщение (формат раздела 24) + рассылка (сейчас dry-run)
orchestrator.py              -- связывает всех агентов в один прогон (пока на демо-данных)
data/ibm_daily_raw.txt       -- реальные котировки IBM для офлайн-тестов (см. "Откуда данные")
tests/test_pipeline.py       -- юнит-тесты на синтетических фикстурах
output/last_run_message.txt  -- результат последнего прогона orchestrator.py
requirements.txt             -- requests (только для load_fmp_daily на VPS)
.env / .env.example          -- секреты (токен, ключ, chat_id) -- .env в .gitignore, никогда не публиковать
```

## Источники данных

**Продакшен (готов к использованию): Financial Modeling Prep.** Леонид
оплатил план Starter, ключ подтверждён рабочим 23 августа. Важный нюанс,
найденный при проверке: FMP 27 августа 2025 перевели весь API на новую
структуру `/stable/...` -- старые пути вида `/api/v3/quote/...` теперь
отдают 403 "Legacy Endpoint" даже с валидным ключом (это не ошибка ключа).
`load_fmp_daily()` в `agents/data_agent.py` уже написан под правильный,
современный путь (`/stable/historical-price-eod/full`) и использует
`requests.get` напрямую -- без какого-либо суммаризирующего слоя между
API и кодом.

Данные от FMP сверены вручную на пересекающемся диапазоне дат (17-21
августа) с котировками Alpha Vantage из офлайн-датасета -- цены совпали
день в день, включая последнюю свечу (233.71/238.72/233.12/235.68)
буквально до цента. Два независимых поставщика согласились -- хороший
знак качества данных.

**Офлайн/демо (для тестов без сети и без ключа): Alpha Vantage demo.**
100 дневных свечей IBM, 2026-03-31..2026-08-21, сохранены в
`data/ibm_daily_raw.txt`. Получены через WebFetch (прямой `curl` к
`alphavantage.co` из песочницы Claude заблокирован сетевым allowlist'ом).
Использовались для разработки и остаются как офлайн-фикстура для
регрессионных прогонов `orchestrator.py`.

## Важно: направление уровней ФИБО (легко перепутать)

Регламент (`claude/fibonacci-reglament.md`, разделы 8-13) определяет точку 1
как ВСЕГДА 100%, а точку 2 как ВСЕГДА 0% -- независимо от направления:

- Нисходящий: точка 1 = HIGH = 100%, точка 2 = LOW = 0%. Это совпадает с
  привычной логикой большинства платформ.
- Восходящий: точка 1 = LOW = 100%, точка 2 = HIGH = 0%. Это ПЕРЕВЁРНУТО
  относительно того, как многие привыкли видеть Fibo retracement по
  умолчанию на графиках (там обычно для аптренда 0%=низ, 100%=верх).

Реализовано буквально по тексту регламента (см. `agents/fibo_agent.py`).
Раз это явно и многократно (5 разделов подряд) прописано в регламенте,
считаю это осознанным решением, а не опиской -- но раз это расходится с
частой практикой, стоит явно подтвердить с Леонидом, прежде чем полагаться
на это в реальных сигналах.

## Что уже работает и проверено на реальных данных

- Глобальный ФИБО на IBM: нисходящий, точка 1 = HIGH 332.46 (2026-06-02),
  точка 2 = LOW 199.19 (2026-07-23) -- совпадает с тем, что было найдено
  вручную в сессии от 19 августа (см. brief.md).
- Локальный ФИБО (черновая версия, окно последних 40 свечей): нисходящий,
  точка 1 = HIGH 311.80 (2026-07-07), точка 2 = LOW 199.19 (2026-07-23).
  Окно 40 свечей подобрано эмпирически -- сам принцип выбора окна для
  локального ФИБО регламент не формализует, это открытый вопрос (см. ниже).
- Price-Behavior Agent нашёл реальное, нетривиальное событие: 17-19 августа
  цена трижды прокалывала уровень 0.236 (230.64) внутри свечи, но
  закрывалась выше -- классифицировано как тест/ложный пробой.
- Verification Agent: чек-лист из 5 пунктов проходит полностью; повторный
  независимый прогон структуры даёт идентичный результат.
- 8/8 юнит-тестов на синтетических фикстурах.
- **Telegram-доставка подтверждена end-to-end, вручную, без VPS.** Бот

  Тестовое сообщение с реальными цифрами по IBM отправлено через прямой URL

- **FMP-ключ подтверждён рабочим** на правильном (`/stable/`) эндпоинте,
  данные сверены с Alpha Vantage -- см. выше.

## LIVE-режим (реальные данные + реальная отправка)

`orchestrator.py` теперь умеет два режима, переключаются переменной окружения:

- **По умолчанию** (`FIB_BOT_LIVE` не задана) -- ровно то же, что и раньше:
  демо-данные IBM, Telegram в DRY RUN. Безопасно запускать сколько угодно
  раз локально, ничего никуда не уходит.
- **`FIB_BOT_LIVE=1`** -- реальные данные через `load_fmp_daily()` (тикер
  берётся из `FIB_BOT_SYMBOL`, по умолчанию тоже IBM) и реальная отправка в
  Telegram (`TELEGRAM_BOT_TOKEN` из окружения). Работает только там, где
  есть обычный интернет -- не в песочнице Claude (см. выше про allowlist).

Сама отправка в `agents/dispatch_agent.py` реализована по-настоящему
(`requests.post` к Bot API), а не заготовкой -- каждому получателю
отдельно, с честным статусом sent/ERROR/EXCEPTION на каждого, без
маскировки неудачи под успех.

## Бесплатный запуск: GitHub Actions (мост до VPS)

Пока не готов VPS, есть рабочий бесплатный вариант получить реальную
отправку каждые 15 минут уже сегодня -- `.github/workflows/fib-bot.yml`.
Это тот же самый пайплайн агентов, без единой правки логики, просто
запущенный по расписанию на серверах GitHub вместо своего постоянно
включённого сервера. Не требует карты вообще -- только бесплатный аккаунт
GitHub.

Как включить:

1. Создать репозиторий на GitHub (можно приватный) и загрузить туда
   содержимое этого архива **как есть** -- `.env` и `secrets/` в архив не
   попадают в принципе, их и не должно быть в репозитории.
2. Settings -> Secrets and variables -> Actions -> New repository secret --
   добавить `TELEGRAM_BOT_TOKEN` и `MARKET_DATA_API_KEY` (значения -- из
   своего `.env`, руками, по одному).
3. Вкладка Actions -> workflow "fib-bot live run" -> Run workflow -- ручной
   тестовый запуск, чтобы сразу проверить, что всё дошло, не дожидаясь
   расписания.
4. Дальше пойдёт само, каждые 15 минут (`cron: */15 * * * *` в workflow-файле).

Два честных ограничения этого моста (оба -- стандартное поведение GitHub
Actions, не специфика этого проекта):

- Расписание не гарантированно точное -- GitHub сам предупреждает, что в
  периоды нагрузки запуск может задержаться на несколько минут.
- Если в репозитории 60 дней подряд не будет ни одного коммита, GitHub
  автоматически отключает scheduled-запуск -- нужно будет вспомнить и
  сделать любой коммит, чтобы включить обратно.

Для случаев, где важна секундная точность расписания и 100% аптайм без
исключений, обычный VPS остаётся более надёжным вариантом -- этот способ
специально для того, чтобы не ждать VPS, чтобы получить реально работающего
бота уже сейчас.

## Чего здесь нет

- Постоянно включённого сервера (VPS) -- по-прежнему не заведён; сейчас
  роль "всегда включённой машины" временно играет GitHub Actions (см. выше).
- Финального списка инструментов для скринера. Весь LIVE-режим сегодня
  проверен только на одном тикере (IBM) -- это было нужно, чтобы
  провалидировать пайплайн end-to-end на настоящих данных, но это НЕ тот
  же продукт, что описан в `claude/brief.md` (Задача №1): там имелся в виду
  скринер по списку из индексов/сырья/акций (черновик списка есть в брифе),
  который отбирает кандидатов на неглубокую коррекцию, а не постоянные
  обновления по одной фиксированной бумаге. Список инструментов и то,
  должен ли бот слать шорт-лист кандидатов вместо разбора одной бумаги --
  открытый вопрос к Леониду, не технический, а по сути продукта.
- Полноценной дневная-vs-часовая сверки в Verification Agent -- пока не
  запускали на внутридневных данных (у FMP Starter они есть, просто ещё не
  тестировали) -- cross-check пока проверен на синтетических фикстурах и на
  повторном прогоне одних и тех же данных.
